# برومبت القيادة — اقرأه في بداية كل مرحلة

أنت تعمل محليًا على منصة «تمكين». مطلوب منك تنفيذ منتج فعلي تدريجيًا، وفق هذه المواصفات، لا واجهات جميلة بأزرار فارغة. تعامل كمهندس منتج يجمع تحليل الأعمال، تصميم تجربة المستخدم، الواجهة، الخادم، البيانات، الأمن، الاختبارات والتشغيل.

## هوية المنتج الملزمة

تمكين تربط رأس المال والجهة المنفذة والناس بنتيجة موثقة عبر ثلاثة مسارات:

1. العمل الخيري: مؤسسة موثقة ← مشروع بميزانية ← مساهمة ← تسوية ← صرف مرحلي ← دليل تنفيذ ← تقرير وإغلاق.
2. العمل والاستثمار: شركة ← عرض تمويل محدد ← فحص وأهلية ← التزام/اكتتاب ← تسوية وتخصيص مثبت ← تقارير وعوائد أو خسائر وإغلاق.
3. حاضنات وفرص عمل: جهة راعية/مشغلة ← فكرة وبرنامج ممول ← ترشح واختيار ← تدريب موثق ← توظيف أو احتضان ← متابعة وقياس أثر.

الطابع البصري والوظيفي: **70% Fintech + Social Impact، 20% Crowdfunding، 10% Humanitarian/Editorial**. حوّل هذه النسب إلى ترتيب المعلومات وكثافتها، ولا تعتبرها نسبة ألوان. المرجع [03](03-DESIGN-SYSTEM.md).

## قبل الكود

- اقرأ تعليمات AGENTS.md الموجودة في المستودع وأسلافه، ثم المرحلة الحالية والملفات التي تعتمد عليها.
- افحص الملفات وgit status. حافظ على أعمال المستخدم. لا تستبدل مشروعًا موجودًا بتطبيق جديد دون سبب موثق.
- اكتب ملخص المرحلة: المطلوب، المخرجات، الاعتماديات، المخاطر الفعلية، طريقة الاختبار.
- تحقق من الإصدارات المتوافقة عند بدء scaffold وثبتها في lockfile وADR. لا تعتمد رقم إصدار من ذاكرتك.
- القرارات العادية تُحسم وفق المواصفات. المتغيرات الخارجية مثل مزود الدفع تستبدل محليًا بـadapter تجريبي واضح؛ لا تجعلها سببًا لإيقاف بناء النظام.

## أثناء العمل

- اللغة TypeScript للواجهة والخادم، SQL للبيانات. البنية Next.js + NestJS + PostgreSQL كما في [10](10-TECHNICAL-ARCHITECTURE.md).
- نفذ vertical slice: migration → domain/service → permission → API → UI → tests. لا تنفذ جميع الشاشات قبل منطق النظام.
- الفرد هو هوية الدخول. Individual وOrganization سياقان للملف والعمل؛ لا تنشئ حساب دخول منفصلًا لكل وظيفة. عضوية المؤسسة لا تجعل أموالها أموال الفرد.
- الصلاحيات تتحقق على الخادم لكل كائن. إخفاء زر وحده ليس حماية.
- لا تحسب المبالغ بالـfloat، ولا تعتبر الرجوع من بوابة الدفع إثبات دفع، ولا تعتبر التعهد سهمًا مملوكًا.
- لا تخلط تبرعًا باستثمار أو مال برنامج تدريبي. إذا اشتركوا في مشروع، فلكل وعاء مصدر واستخدام ودفتر فرعي مستقل.
- اربط كل إجراء في `screens` بتنفيذ أو حالة معلنة غير متاحة مع تفسير. ممنوع زر لا يفعل شيئًا، أو إشعار نجاح قبل حفظ الخادم.
- التزم بـRTL، لوحة المفاتيح، قارئات الشاشة، التباين، عرض الهاتف، وجميع loading/empty/error/forbidden/pending states.
- البيانات التجريبية مؤشرة «تجريبية». بيئة demo ممنوعة من الاتصال بمزود إنتاج أو إرسال رسائل حقيقية.
- إذا ظهرت حاجة لصفحة أو إجراء جديد، أضف عقدها إلى سجل الشاشات أولًا، مع الإذن والمدخلات والأثر والاختبارات.
- لا تدخل الذكاء الاصطناعي في قرار قبول مستفيد أو مستثمر أو صرف المال. المطابقة الأولية قواعد شفافة قابلة للمراجعة.

## نهاية المرحلة

1. شغّل الاختبارات المطلوبة في ملف المرحلة، مع فحص lint/types/build المناسب.
2. تحقق بصريًا من الواجهة بالعربية على الهاتف وسطح المكتب عند تعديلها.
3. حدّث PROGRESS.md: منفذ، اختبار فعلي ونتيجته، عوائق، ملفات تغيرت، الخطوة التالية.
4. حدّث TRACEABILITY.md بروابط الكود والاختبارات ومعرفات الصفحة والإجراء.
5. لا تكتب «مكتمل» إذا كان المزود mock فقط؛ اكتب «مكتمل محليًا باستخدام محاكي».
6. اذكر أوامر التشغيل الفعلية، الحسابات التجريبية، وأي حدود باقية. لا تنشئ commit أو تنشر خارجيًا إلا ضمن تعليمات المستخدم الخاصة بتلك الجلسة.
