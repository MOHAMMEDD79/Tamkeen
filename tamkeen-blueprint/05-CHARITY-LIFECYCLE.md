# 05 — دورة العمل الخيري

## الكيانات والمسؤوليات

الجهة تملك المشروع؛ ProjectManager مسؤول الميزانية والمراحل؛ FinanceMaker يطلب الصرف؛ FinanceApprover يعتمد؛ منصة/مزود الدفع ينفذ وفق النموذج المحدد؛ مسؤول الحالة يدير المستفيدين بصورة خاصة؛ المتبرع يرى مساهمته والشفافية المنشورة.

## آلة الحالات

`draft → submitted → in_review → changes_requested → submitted` أو `in_review → approved → published → funding_closed → executing → impact_review → completed → archived`.

يسمح ببدء تنفيذ مرحلة أثناء التمويل إذا نصت سياسة المشروع على ذلك؛ حالة المشروع لا تغني عن حالة كل مرحلة. حالات جانبية: paused, cancelled, rejected. التوقف لا يصفر الأموال. الإلغاء يطلق reconciliation وخطة رد/التزام، ولا يصير completed تلقائيًا.

| الانتقال | من ينفذه | الشرط | الأثر |
|---|---|---|---|
| إرسال للمراجعة | مدير المشروع | حقول وميزانية وأدلة مكتملة | قفل snapshot وإشعار المراجع |
| طلب تعديل | مراجع محتوى | أسباب على مستوى الحقول | نسخة جديدة مع حفظ القديمة |
| نشر | مراجع المحتوى | توثيق صالح، خطة صرف وسياسة هدف | إدراج عام وإتاحة مساهمة |
| إيقاف جمع | مدير المشروع/مخاطر | سبب وتقييم الالتزامات | منع عمليات جديدة؛ انتظار المعلقة |
| طلب صرف مرحلة | FinanceMaker | مرحلة مستحقة ورصيد متاح وأدلة | حجز مبلغ ومنع صرف مزدوج |
| اعتماد صرف | FinanceApprover | ليس المنشئ، مستفيد ثابت | تفويض مرتبط بنسخة الطلب |
| تأكيد تنفيذ | مدير المشروع | فواتير/صور/قياس إنجاز | إرسال للمراجعة لا إكمال ذاتي |
| إغلاق | مراجع أثر مخول | فروقات محلولة وتقارير منشورة | تقرير ختامي وإشعار الداعمين |

## رحلة المساهمة

اكتشاف → مراجعة الجهة/الهدف/الموقع/المراحل/سياسة الأموال → اختيار مبلغ وعملة ثابتة للمشروع → اختيار الظهور باسم أو مجهول → ملخص إجمالي الرسوم والمبلغ المخصص → إنشاء payment intent → دفع لدى المزود → صفحة «بانتظار التأكيد» → webhook موثق → إيصال حالة مدفوعة → تسوية → تحديث تقدم التمويل → متابعة أثر → إغلاق أو استرداد.

الإصدار الأول يتطلب حسابًا للمساهمة لتوفير سجل واسترداد واضح؛ الاستكشاف دون حساب. الدفع المتكرر وتبرعات الضيف مؤجلان. لا تخزن بيانات البطاقة محليًا.

## هوية المساهم

`public_visibility = named | anonymous`. الافتراضي anonymous مع شرح بسيط. العامة يرون «فاعل خير» ومبلغًا فقط إذا وافق المساهم على إظهار المبلغ أيضًا. تظهر هويته في إيصال حسابه؛ طاقم التشغيل المصرح يمكنه الوصول للهوية اللازمة للتسوية والنزاع، ويُدقق ذلك. إخفاء عام لا يعني إخفاء عن معالجة الدفع. لا يظهر البريد أو الاسم في API العام أو HTML أو analytics أو export عام. تغيير الخصوصية يحدث قائمة المساهمين والـcache.

## قواعد الهدف

- سياسة التمويل تختار عند النشر: flexible أو all_or_nothing. تبقى ثابتة بعد أول مساهمة.
- flexible: يمكن التنفيذ جزئيًا وفق ميزانية مرحلية؛ نهاية المدة تحتاج خطة نطاق أصغر أو استرداد المتاح وفق الشروط المعلنة.
- all_or_nothing: يمنع صرف الأموال قبل بلوغ الهدف المؤهل ونهاية نافذة الحسم؛ إن فشل الهدف تنشأ استردادات وفق سياسة منشورة. مدة الاحتفاظ/الحجز الفعلي تتبع قدرة المزود ولا تفترض أن authorization يستمر طوال الحملة.
- التمويل الزائد ممنوع افتراضيًا. يحجز checkout السعة لفترة محدودة؛ وصول دفعتين متزامنتين أو تأكيد متأخر يعالج بسياسة overflow refund دون تجاهل مال مقبوض.
- «التمويل المحقق» = المقبوض المؤكد ناقص الاسترداد المؤكد؛ «المتاح للصرف» بعد التسوية والرسوم والحجوزات. اعرض التعريفين ولا تساوهما.

## صفحة الشفافية

هدف، مقبوض، مسترد، رسوم، صافي مسوّى، مصروف، محجوز، متاح؛ ميزانية أصلية ونسخ تعديلها؛ مراحل مخططة وفعلية؛ مسؤولون بأسماء عمل مسموحة؛ مدينة وخريطة مناسبة؛ أدلة منقحة؛ تقارير بتاريخ إصدار. تغيير الميزانية بعد التمويل يحتاج سبب ومراجعة وإشعار؛ استخدام الأموال لغرض آخر ليس تعديل نص عاديًا.

## المستفيدون

طلب مساعدة خاص → موافقة مشاركة مع جهة بعينها → فحص أهلية → طلب توضيح → قبول/رفض مسبب → ربط بمرحلة دعم → إثبات تسليم أو خلاف → إغلاق وملاحظات متابعة. لا ربط تلقائي لاسم مستفيد بقائمة عامة. يمنع احتساب تسليم معترض عليه كأثر موثق حتى الحسم.

## حالات فشل واجبة

فشل دفع، غلق نافذة المزود، webhook متكرر أو متأخر، مساهمة فوق السعة، انتهاء التوثيق، تراجع المزود بعد التسوية، مشروع ملغى بعد صرف جزئي، نزاع فاتورة، فقد مستند، تغير بنك المستفيد، نقص رصيد استرداد. لكل حالة سجل مسؤول ومهلة تصعيد وحالة مرئية للمتأثر؛ لا تعديل يدوي لرصيد لتجميل النتائج.
