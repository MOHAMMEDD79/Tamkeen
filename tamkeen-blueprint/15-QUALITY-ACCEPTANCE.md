# 15 — جودة واختبارات القبول

## بوابات كل مرحلة

types/lint؛ اختبارات قواعد المجال؛ integration حقيقية مع PostgreSQL للمعاملات؛ API permissions على الكائنات؛ Playwright للرحلة المتأثرة؛ فحص عربي RTL وهاتف ولوحة مفاتيح. لا تستخدم mocks بدل اختبار قيود DB المالية أو عزل الجهات. لا تكتب snapshot لكل نص؛ اختبر السلوك والمخاطر.

## معايير عامة

- كل إجراء في سجل الشاشات يملك implementation + happy path + رفض صلاحية/حالة + خطأ قابل للاستعادة.
- 401/403/404/409 لا تعرض نجاحًا؛ retries لا تكرر المال أو الطلب.
- كل نموذج يحفظ المسودة أو يحذر قبل المغادرة؛ كل list لها empty/loading/error وpagination.
- لا أخطاء console غير مبررة؛ لا overflow عند 360px؛ focus يعود بعد dialog.
- الروابط العامة لا تكشف بيانات خاصة في HTML/RSC payload/API/cache/exports.

## مصفوفة الاختبارات الحرجة

| ID | السيناريو | النتيجة المقبولة |
|---|---|---|
| AUTH-01 | فرد بقدرات متعددة وعضويتين | تبديل صحيح بلا تسرب caches أو إذن |
| AUTH-02 | تعديل orgId في كل detail/export/mutation | رفض بلا كشف كائن |
| AUTH-03 | Maker يحمل Approver ويعتمد طلبه | رفض بهوية actor |
| CH-01 | نشر مشروع وتبرع مجهول وإيصال | هوية خاصة سليمة وعامة مخفية |
| CH-02 | بلوغ هدف متزامن من دفعتين | سياسة سعة/overflow حتمية ولا فقد مال |
| FIN-01 | تكرار webhook 10 مرات | قيد وإيصال منطقي واحد |
| FIN-02 | أحداث بترتيب معكوس | لا رجوع حالة ولا تكرار أثر |
| FIN-03 | صرفان يتجاوزان مجموع المتاح | واحد/كلاهما حسب السعة؛ لا سالب غير مفسر |
| FIN-04 | timeout بعد نجاح مزود | inquiry يثبت النجاح دون دفع ثانٍ |
| FIN-05 | refund متزامن/جزئي | لا يتجاوز remaining refundable |
| FIN-06 | إعادة بناء الدفتر | الأرصدة تطابق قبل وبعد |
| INV-01 | اهتمام ثم التزام ثم دفع ثم تخصيص | holding فقط بعد إثبات allocation |
| INV-02 | مثال مليون سهم + مئة ألف جديد | حساب نسبة 1000/1100000 صحيح |
| INV-03 | إفصاح جديد أو أهلية منتهية | منع متابعة دون معالجة نسخة/أهلية |
| INV-04 | فشل الحد الأدنى | إغلاق بعد حل كل التزامات واستردادات |
| PRG-01 | آخر مقعد مع قبولين متزامنين | لا تجاوز سعة |
| PRG-02 | قبول تدريب دون عرض عمل | لا يزيد مؤشر موظفين |
| PRG-03 | تعديل حضور بعد استحقاق | revision واعتراض/تسوية دون دفع صامت |
| JOB-01 | قبول عرض ثم عدم بدء | start_pending لا started |
| JOB-02 | متابعة بلا رد | unknown لا retained |
| PRIV-01 | تغيير مساهمة إلى مجهولة | حذف الاسم من كل projection عامة/cache |
| DOC-01 | ملف مصاب أو نوع مزيف | حجر ومنع وصول حتى قرار |
| OPS-01 | انقطاع email worker ثم replay | لا فقد ولا مضاعفة إشعارات |
| OPS-02 | استعادة DB وstorage مرجعيًا | ملفات وقيود وIDs مترابطة |

## الأداء والإتاحة

ميزانية محلية أولية قابلة للقياس: قراءة API اعتيادية p95 <500ms على dataset موثق دون وقت المزود، تفاعل واجهة دون تجميد، query plans تمنع N+1، قوائم paginated. سجل الجهاز والحجم قبل الادعاء بالنتيجة. استهدف WCAG 2.2 AA كمتطلب تصميم، مع فحص آلي ومراجعة بشرية للرحلات الأساسية؛ الفحص الآلي وحده لا يثبت المطابقة.

## تسليم اختبار

احفظ الأمر والبيئة والنتيجة ووقت التشغيل واسم السيناريو وأدلة screenshots للواجهات المتغيرة في docs/qa/part-XX. الاختبارات المخطط لها ليست اختبارات ناجحة. أي failure يبقى مفتوحًا أو موثقًا مع أثره، ولا يخفى بـskip بلا سبب.
