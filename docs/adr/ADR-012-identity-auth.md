# ADR-012 — الهوية والجلسات المحلية

الحالة: مطبق محليًا ضمن شريحة PART-02، وليس اعتمادًا للإنتاج.

## القرار

- الحفاظ على TypeScript وNestJS وPostgreSQL وNext.js الحالية. Better Auth 1.7.5 يتولى كلمات المرور والتحقق والاسترداد؛ لا بروتوكول كلمات مرور خاص.
- User واحد وله IndividualProfile متعدد القدرات. Organization لها Party مستقلة وMembership لكل فرد. اختيار Investor لا يمنح أهلية مالية.
- خدمة IdentityService تستقبل actor من جلسة موثقة فقط؛ كل قراءة وكتابة مؤسسة تفحص العضوية الحالية والجهة والحالة. تغيير السياق ليس إذنًا ولا يبدل هوية الفرد.
- Owner لا يملك صلاحيات صرف/اعتماد/تصدير مالي. التفويض لا يتجاوز صلاحيات المفوض، ولا يمنح Owner عبر دعوة أو تحديث عضوية.
- الجلسة Cookie HttpOnly وSameSite=Lax؛ Secure في إعداد الإنتاج. التخزين يحتوي SHA-256 لرمز الجلسة، عبر adapter يطبق التحويل عند الكتابة والبحث. Cookie cache معطل كي لا تبقى العضوية الملغاة صالحة.
- حارس مسارات الأعمال يمدد الجلسة 24 ساعة بتحديث مشروط كل ساعة، مع إبقاء token نفسه مخزنًا كـSHA-256. هذا يغطي استخدام API للأعمال الذي لم يفعّل تحديث Better Auth تلقائيًا في اختبار التكامل.
- كل mutations الخاصة بالهوية تفحص Origin. مسارات Better Auth المسموحة فقط مركبة على الخادم؛ لا تعرض واجهات قائمة الجلسات الأصلية التي تفترض استعادة token من DB.
- الدليل المحاسبي للهوية append-only في SQL. Party يجب أن تشير إلى فرد أو جهة بالضبط. trigger مؤجل يمنع ترك جهة نشطة بلا مالك نشط.
- إنشاء المؤسسة والمالك والـParty والتدقيق ذري. الدعوة وتسليمها إلى البريد المحلي ذريان. إيقاف العضوية وإلغاء جلسات العضو ذريان. الإلغاء الحالي يشمل كل جلساته كخيار محافظ، لا جلسة سياق واحدة فقط.
- معاينة الدعوة تتطلب جلسة لبريد موثق مطابق وتعيد حقولًا عامة محددة فقط. القبول والرفض والإلغاء حالات نهائية متنافية بقيد SQL، وتشترك في قفل الجهة بحيث يفوز إجراء واحد عند التزامن؛ الرفض يسجل المدعو والوقت دون إنشاء عضوية.
- إدارة الجلسات تقرأ metadata فقط ولا تعيد hash أو bearer token. إلغاء الجلسة يحذف سجلًا مملوكًا للمستخدم داخل معاملة مع audit؛ محاولة إلغاء جلسة مستخدم آخر لا تكشف وجودها.
- `local-outbox` يحفظ روابط الاختبار في LocalAuthMail؛ الوصول إليه عبر CLI محلي فقط، وليس HTTP. غير مسموح خارج demo/test. لا رسائل خارجية أُرسلت.
- التسجيل يقبل إصدار الشروط الحالي فقط ويسجل `termsAcceptedAt` من الخادم. رمز تحقق البريد يُتحقق من توقيعه ثم يُحجز ذريًا بمعرف مشتق من SHA-256 قبل التنفيذ؛ لذلك يفوز طلب واحد عند الفتح المتزامن وتتحول الإعادات إلى نتيجة خطأ.

## مواءمة عقود الخطة

مسارات المصادقة في الخطة أسماء منطقية. التنفيذ يستخدم عقود المكتبة بدل إعادة تنفيذ بروتوكولها:

| عقد الخطة | التنفيذ تحت /api/v1 |
|---|---|
| POST /auth/register | POST /auth/sign-up/email |
| POST /auth/login | POST /auth/sign-in/email |
| POST /auth/recovery | POST /auth/request-password-reset |
| POST /auth/verification-resend | POST /auth/send-verification-email |
| POST /auth/verify | GET /auth/verify-email عبر رابط المكتبة |
| POST /auth/reset | POST /auth/reset-password |
| POST /me/capabilities | ضمن PATCH /me/profile مع version |
| POST /orgs/:id/members/:uid/suspend | PATCH /orgs/:id/members/:uid مع status=suspended وversion |

كل مسارات الأعمال الأخرى تتبع الخطة. يلزم إكمال OpenAPI قبل إغلاق PART-02. هذه مواءمة تنفيذ موثقة، ولا تعني اكتمال قبول كل Action.

## حدود معروفة ونقطة متابعة

- MFA ومراجعة التوثيق وإدارة الجلسات الانتقائية منفذة محليًا؛ نقل الملكية وتغيير البنك ومنح موظفي المنصة لم تنفذ بعد. شروط التشغيل النهائية تحتاج محتوى واعتمادًا قانونيًا مستقلًا عن إصدار التجربة المحلي.
- واجهات العرض وظيفية أولية؛ نظام التصميم المفصل في PART-03 لم يبدأ.
- اختبارات HTTP أثبتت التسجيل والموافقة ذات النسخة والتحقق المتزامن أحادي الاستخدام والجلسة والاسترداد والإلغاء. يلزم توسيعها إلى refresh وrotation واختبار مهلة rate limit تحديدًا.
- البنية الحالية لتحديد IP تعتمد socket المحلي؛ خلف reverse proxy قد تتشارك الطلبات عنوانًا واحدًا. يلزم إعداد proxy موثوق وحدود موزعة قبل تشغيل خارجي.
- لا تخزين وثائق، ولا إرسال بريد حقيقي، ولا أهلية مالية أو مدفوعات. وجود hooks إعداد الإنتاج لا يعني أن نشر الإنتاج جاهز.
