# تمكين — المستودع المحلي

حالة التنفيذ: **PART-01 وPART-03 حتى PART-13 متحققة محليًا، وPART-14 في بوابة التسليم، وPART-02 ما زالت بوابته المحمية المستقلة قيد التنفيذ**. يعمل الأساس التقني والهوية والمؤسسات ونظام التصميم والسطح العام ودورات العمل الخيري والاستثمار والتدريب والتوظيف والاتفاقات والبدلات والشهادات والاحتضان والمساعدة والتطوع والدعم والتشغيل محليًا على Next.js وNestJS وPostgreSQL فعلية. راجع [سجل التقدم](tamkeen-blueprint/PROGRESS.md).

> **المال يعمل بمحاكٍ فقط.** لا يوجد مزود دفع ولا بريد خارجي، ولم تنتقل أي أموال حقيقية. `MONEY_ENABLED` و`INVESTMENT_ENABLED` يجب أن يبقيا `false`، وأي محاولة تفعيل تفشل عند startup.

## المتطلبات

- Node.js 24.19.0 ضمن خط 24.
- pnpm 11.19.0.
- Windows x64: قاعدة PostgreSQL محمولة مرفقة عبر dependency تطوير؛ لا تحتاج تثبيت خدمة Windows أو Docker.
- بديل Docker في `infra/compose.yaml`؛ لا تشغله مع القاعدة المحمولة على المنفذ نفسه.

## أول تشغيل

من مجلد Tamkeen في PowerShell:

```powershell
pnpm install --frozen-lockfile
pnpm setup
pnpm build
pnpm db:local
```

اترك الطرفية الأخيرة مفتوحة. في طرفية ثانية:

```powershell
pnpm db:migrate
pnpm db:seed
pnpm demo:money
pnpm dev
```

`db:seed` ينشئ جهات ومشاريع وخططها (حملة وميزانية ومراحل) — خطة لا رصيد. `demo:money` اختياري: ينشئ مساهمات تجريبية مؤكدة عبر المحاكي والمسار الحقيقي نفسه، ولا يكتب أي صف مال مباشرة في القاعدة.

افتح [الواجهة المحلية](http://127.0.0.1:3000) — تعيد التوجيه إلى `/ar` أو `/en` حسب تفضيل المتصفح، والعربية هي الاحتياطي. شاشات مراجعة التصميم على [/ar/design](http://127.0.0.1:3000/ar/design). الخادم على [فحص الجاهزية](http://127.0.0.1:4000/api/v1/health/ready) و[فحص الحياة](http://127.0.0.1:4000/api/v1/health/live).

`setup` ينشئ `.env` بأسرار محلية عشوائية ولا يستبدل الملف الموجود. قاعدة البيانات تبقى في `.local/postgres` بعد الإيقاف. الملفات السرية والبيانات وnode_modules ونتائج البناء مستبعدة من Git. لا تستخدم هذه القاعدة المحمولة للإنتاج.

## تشغيل لاحق

طرفية للقاعدة: `pnpm db:local`. طرفية للخدمات: `pnpm dev`. تغييرات API/worker تراقب بواسطة tsx؛ تغيير package مشتركة يتطلب إعادة بنائها، وتغيير schema يتطلب generate/build وmigration مناسبة. Ctrl+C يوقف كل مجموعة بدأت من طرفيتها. إعادة تحميل الصفحة تحدّث نتيجة الاتصال الفعلية.

## التحقق

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:integration
pnpm test:e2e
pnpm demo:stories
pnpm ops:restore-rehearsal
```

اختبار integration يتطلب قاعدة محلية عاملة وكل migrations مطبقة. يتحقق من الصحة والمصادقة والموافقة ذات النسخة وعزل الجهات وتزامن الدعوات وتغيير الحساب البنكي بمراجعة مستقلة ودورة حياة المشروع الخيري ومطابقة عقد OpenAPI للمسارات المسجلة، دون كشف بيانات الاتصال. ويتحقق من المال على قاعدة فعلية: توازن الدفتر، وidempotency الـwebhook، ومنع التمويل الزائد، وخصوصية المساهم، وأن **لا عمود مال واحد** من نوع عائم، وفصل المسؤوليات في الصرف، ومنع الصرف فوق الرصيد، وحسم النتيجة المجهولة بالاستعلام دون دفع مزدوج، وحدود الاسترداد، وأن إعادة المطابقة لا تكتب أي قيد. `pnpm db:seed` قابل للتكرار ولا ينشئ أموالًا؛ الأموال التجريبية من `pnpm demo:money` وحده، وهو يترك طلب الصرف عند «بانتظار الاعتماد» عمدًا لأن الخطوتين التاليتين قرارا شخصين آخرين. و`pnpm demo:offering` ينشئ عرضين استثماريين بأرقام المثال المحسوب في 06 ويتركهما مسودة للسبب نفسه، و`pnpm demo:subscription` يسوق دورة الاستثمار كاملة عبر الخدمات نفسها: اعتماد مستقل، وفتح، واكتتاب ودفع وتسوية عبر الـwebhook الموقّع، وإغلاق، وجدول تخصيص يعتمده مراجع مستقل، ثم تقرير وتوزيع. و`pnpm demo:program` يسوق دورة التدريب كذلك: برنامج يعتمده مراجع مستقل، وتفتح الجهة تقديمه، وثلاثة طلبات على مقعدين فتظهر قائمة انتظار حقيقية، ويُسند مدرب لدفعة واحدة — ويترك الدعوات دون قبول عمدًا، لأن قبول المقعد فعل صاحبه.

بعد أي تعديل على `database/schema.prisma` شغّل `pnpm db:generate` ثم `pnpm --filter @tamkeen/database build` قبل `pnpm typecheck`، لأن التطبيقات تستهلك المخرجات المبنية لا المصدر.

## الأجزاء

- `apps/web`: صفحات عامة مُخدَّمة من الخادم بلغتين (`/ar` و`/en`) للاستكشاف والخريطة والجهات والمشاريع والأثر، ومسارات الهوية والمؤسسات والفريق. لا mock.
- `apps/api`: health، وهوية ومؤسسات، ومشاريع خيرية، ومال بدفتر مزدوج، واستثمار من الإفصاح حتى التخصيص، وبرامج وتوظيف وتمكين، ودعم وتدقيق وعمليات وexports وتقارير أثر — **كل المال عبر محاكٍ فقط**.
- `apps/worker`: heartbeat، وتسليم إشعارات/outbox مع retry وdead-letter، ومعالجة export jobs. التسوية المالية المجهولة لا يعاد تشغيلها عميانًا؛ تحسم بالاستعلام.
- `packages/config`: تحقق من env ومنع تفعيل الخدمات المالية/البريد الخارجي.
- `packages/contracts`: عقد OpenAPI للمسارات المنفذة، يمسكه اختبار انحراف يقارنه بالمسارات المسجلة فعليًا، وسجل الأفعال الذي يفصل المنفذ عن المعلن غير متاح.
- `packages/ui`: نظام التصميم — tokens مصدرها TypeScript، أنماط بـlogical properties، مكونات accessible، قشرة التطبيق، وأدوات اللغة.
- `database`: Prisma schema وSQL migration وclient وseed.
- `scripts`: تجهيز البيئة وتشغيل الخدمات وقاعدة البيانات.
- `.github/workflows/ci.yml`: بناء وفحوص واختبار PostgreSQL عند رفع المستودع إلى GitHub؛ لم يُرفع بعد.
- [الخطة الكاملة](tamkeen-blueprint/README.md) و[التقدم](tamkeen-blueprint/PROGRESS.md).

## Docker الاختياري

بعد ضبط `POSTGRES_PASSWORD` بما يطابق `.env`:

```powershell
docker compose -f infra/compose.yaml up -d postgres
```

Redis وMailpit ضمن profile `extras` كإعداد مساعد للمراحل القادمة. Docker غير متاح على الجهاز وقت التحقق، لذلك لم تُجرّب هذه الخدمات. تخزين S3 والـqueues يضافان عند أول ميزة تحتاجهما؛ لا تُعلن جاهزيتهما من متغيرات env وحدها.

## حدود المرحلة

لا مزود دفع أو بريد خارجي أو سجل أسهم قانوني أو تداول ثانوي. كل تخصيص وحصة معلَّمان `simulated`، ولا قناة صرف حقيقية إلى شخص. `MONEY_ENABLED` و`INVESTMENT_ENABLED` يبقيان false حتى تحسم بوابات الإطلاق القانونية والتشغيلية. لا مزود خرائط أو ترخيص tiles، ولا S3/Redis إنتاجيان؛ التخزين والـoutbox محليان. راجع [بوابات الإطلاق والفجوات الخارجية](docs/operations/LAUNCH-GATES.md) و[دليل التشغيل](docs/operations/RUNBOOK.md).
